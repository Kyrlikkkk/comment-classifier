# Comment Classifier

## Описание проекта

Comment Classifier - веб-приложение для определения тональности текстовых комментариев. Приложение предназначено для разделения отзывов на положительные и отрицательные.

Пользовательский интерфейс позволяет перейти к классификатору, зарегистрироваться, войти в систему, просмотреть профиль и историю запросов.

Backend обеспечивает работу с базой данных, хранение пользователей и комментариев, а также выполнение операций с записями через API.

## Основные экраны

- Главная страница.
- Страница входа.
- Страница регистрации.
- Страница классификатора.
- Профиль пользователя с историей запросов.

## Основные пользовательские сценарии

1. Пользователь открывает главную страницу приложения.
2. Нажимает кнопку «Начать работу».
3. Переходит к классификатору или странице входа.
4. При отсутствии аккаунта переходит на страницу регистрации.
5. После регистрации пользователь может перейти на страницу входа.
6. После входа пользователь переходит в профиль.
7. Пользователь открывает классификатор.
8. Вводит текст комментария и запускает его анализ.
9. Приложение определяет тональность комментария.
10. Результат анализа сохраняется в истории пользователя.

## Структура базы данных

В базе данных `comment_classifier` используются две основные таблицы: `users` и `comments`.

### Таблица `users`

|  Поле            | Тип         | Описание                      |
|------------------|-------------|-------------------------------|
| `id`             | Integer     | Первичный ключ пользователя   |
| `username`       | String(50)  | Имя пользователя, уникальное  |
| `email`          | String(255) | Электронная почта, уникальная |
| `hashed_password`| String(255) | Хеш пароля                    |

Пароли не хранятся в открытом виде.

### Таблица `comments`

| Поле         | Тип        | Описание                               |
|--------------|------------|----------------------------------------|
| `id`         | Integer    | Первичный ключ комментария             |
| `text`       | Text       | Текст комментария                      |
| `sentiment`  | String(20) | Тональность: `positive` или `negative` |
| `created_at` | DateTime   | Дата и время создания записи           |
| `user_id`    | Integer    | Внешний ключ пользователя              |

Между таблицами установлена связь «один ко многим»: один пользователь может иметь несколько комментариев, а каждый комментарий связан с одним пользователем через поле `user_id`.

## API

Backend предоставляет REST API для работы с пользователями и комментариями.

| Метод  | Endpoint                 | Назначение                     |
|--------|--------------------------|--------------------------------|
| POST   | `/users/`                | Создание пользователя          |
| GET    | `/users/`                | Получение списка пользователей |
| GET    | `/users/{user_id}`       | Получение пользователя по ID   |
| PATCH  | `/users/{user_id}`       | Изменение данных пользователя  |
| DELETE | `/users/{user_id}`       | Удаление пользователя          |
| POST   | `/comments/`             | Создание комментария           |
| GET    | `/comments/`             | Получение списка комментариев  |
| GET    | `/comments/{comment_id}` | Получение комментария по ID    |
| PATCH  | `/comments/{comment_id}` | Изменение комментария          |
| DELETE | `/comments/{comment_id}` | Удаление комментария           |

При создании комментария указывается `user_id` существующего пользователя. Список комментариев можно фильтровать по пользователю.

API проверяет входные данные и возвращает соответствующие HTTP-коды, например `201` при создании записи, `404` при отсутствии записи и `422` при ошибке валидации.

## Настройка и запуск backend

Для запуска необходимы Python 3.12 или совместимая версия, PostgreSQL и установленный Git.

### 1. Создание виртуального окружения

Откройте терминал в папке `backend` и выполните:

```powershell
python -m venv .venv
```

Активируйте виртуальное окружение:

```powershell
.\.venv\Scripts\Activate.ps1
```

Если PowerShell не позволяет активировать окружение, команды можно выполнять напрямую через `.\.venv\Scripts\python.exe`.

### 2. Установка зависимостей

```powershell
python -m pip install -r requirements.txt
```

### 3. Настройка базы данных

Запустите PostgreSQL и создайте базу данных `comment_classifier`, а также пользователя с необходимыми правами.

В папке `backend` создайте файл `.env` на основе `.env.example` и укажите строку подключения:

```env
DATABASE_URL=postgresql+psycopg://classifier_user:YOUR_PASSWORD@localhost:5432/comment_classifier
```

Замените `YOUR_PASSWORD` на пароль созданного пользователя PostgreSQL. Файл `.env` содержит секретные данные и не должен добавляться в Git.

### 4. Создание таблиц

Из папки `backend` выполните:

```powershell
python -c "from app.database import Base, engine; from app import models; Base.metadata.create_all(bind=engine); print('Таблицы созданы!')"
```

Команда создаёт отсутствующие таблицы на основе моделей SQLAlchemy.

### 5. Запуск API

Из папки `backend` выполните:

```powershell
python -m uvicorn app.main:app --reload
```

После запуска API будет доступно по адресу:

http://127.0.0.1:8000

Интерактивная документация Swagger UI:

http://127.0.0.1:8000/docs

Через Swagger можно выполнять запросы к API и проверять CRUD-операции.

## Запуск frontend

Откройте второй терминал в корневой папке проекта `comment-classifier`.

Установите зависимости:

```bash
npm install
```

Запустите сервер разработки:

```bash
npm run dev
```

Vite выведет локальный адрес приложения в терминал, обычно:

http://localhost:5173

Для корректной работы frontend с backend потребуется настройка взаимодействия с API.

## Проверка работоспособности

В ходе проверки backend были выполнены следующие операции:

- Создание пользователя - `201 Created`.
- Получение списка пользователей - `200 OK`.
- Создание комментария - `201 Created`.
- Получение комментариев - `200 OK`.
- Обновление комментария - `200 OK`.
- Удаление комментария - `204 No Content`.
- Запрос несуществующего пользователя - `404 Not Found`.
- Отправка некорректных данных - `422 Unprocessable Entity`.

Проверки подтвердили работоспособность основных CRUD-операций и валидации входных данных.
